5. Protocol v1
   - Jedno połączenie = jedna logiczna notatka.
   - Typed commands: recording.start, recording.stop, memory.retry.
   - schema_version=1, extra=forbid, discriminator=type.
   - Klient podaje ingestion_id; nie może podać session_id.

6. Audio wire format
   - Raw binary pcm_s16le, 16000 Hz, mono.
   - Brak base64 i brak alternatywnych formatów w v1.
   - Serwer zapisuje chunks strumieniowo, bez trzymania całego audio w RAM.

7. Chunk/total limits
   - Maksymalna binary frame: 262144 bajty.
   - Maksymalnie 19200000 bajtów PCM, czyli 10 minut.
   - Wymagana parzysta liczba bajtów PCM16.
   - Limit jest liczony na podstawie faktycznie odebranych binary frames.

8. Connection state machine
   - CONNECTED -> RECORDING -> PROCESSING -> PENDING_SAVE -> COMPLETED.
   - Invalid transition emituje protocol.invalid_message i close 1002.
   - Po saved albo empty final serwer zamyka połączenie kodem 1000.

9. Temp WAV lifecycle
   - Temp WAV powstaje przez tempfile poza repo i jest własnością adaptera.
   - Usuwany po STT success/failure, protocol failure i disconnect.
   - Przy anulowaniu thread-backed inference runtime czeka, aż provider przestanie
     używać ścieżki, zanim adapter ją usunie.
   - Testy cleanup PASS; brak pozostawionych fixtures.

10. Event ordering
    - Success: ready 1, final 2, saving 3, saved 4.
    - Empty: ready 1, final 2.
    - Save failure/retry: ready 1, final 2, saving 3, error 4,
      saving 5, saved 6.
    - Wszystkie events jednego połączenia mają jeden session_id.

11. Event sequence implementation
    - VoiceSession zachowuje własne ready/final sequence.
    - WebSocketEventSink waliduje contiguous sequence i session_id.
    - Transport kontynuuje od następnej sequence dla persistence/error events.
    - Serializacja odbywa się wyłącznie przez event_to_jsonable.
