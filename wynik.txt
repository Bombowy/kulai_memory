## 7. Publiczne API application transcription

Dodano `TranscriptionService(provider=...)` oraz:

`await service.transcribe(request=TranscriptionRequest(...)) -> TranscriptionResult`

Serwis deleguje do istniejącego `kulai_transcription.transcribe`, zachowując
request, input type, language hint, mode i timestamp mode bez duplikowania
walidacji reusable modułu.

## 8. Zmiana VoiceSession

`VoiceSession` przyjmuje opcjonalny `TranscriptionService`. Aktywna sesja może
wykonać `await session.transcribe(request=...)`. Metoda zwraca pełny
`TranscriptionResult` i po sukcesie emituje dokładnie jeden `transcript.final`.
Nie emituje sztucznych `transcript.partial`.

## 9. Concurrency semantics

Jeden lifecycle lock obejmuje start, transcribe i close:

- równoległe transkrypcje tej samej sesji są serializowane;
- ich eventy mają deterministyczne, unikalne sequence numbers;
- `close()` wywołane podczas aktywnego await inference czeka na zakończenie
  requestu i emisję final eventu, a następnie zamyka sesję;
- nie dodano task queue.

## 10. Cancellation semantics

- `asyncio.CancelledError` propaguje i nie jest mapowany na transcription failure;
- cancellation podczas oczekiwania na providera pozostawia sesję ACTIVE;
- nie powstaje `transcript.final` ani żaden zapis;
- native CTranslate2 worker może dokończyć pracę w tle i nie jest siłowo
  zatrzymywany;
- po cancellation caller może zamknąć sesję; zamknięcie nie udaje zatrzymania
  już uruchomionego kodu native.

Cancellation podczas samego event delivery oznacza FAILED, ponieważ wynik nie
został niezawodnie dostarczony.

## 11. Silence semantics

Pusty `TranscriptionResult.text` jest poprawnym wynikiem. VoiceSession emituje
wtedy `transcript.final` z pustym tekstem. Nie jest to błąd providera.

## 12. Error safety

Provider failure jest mapowany na `VoiceSessionTranscriptionError` z bezpieczną,
stałą wiadomością. Oryginalny typed error pozostaje jako `__cause__`. Host nie
loguje audio, ścieżki, transcriptu, raw provider payload ani raw exception.

Test z `password=top-secret`, `PRIVATE_TRANSCRIPT_SENTINEL` i prywatną ścieżką
potwierdza brak tych wartości w publicznym wyjątku oraz publicznym error event.

## 13. Event ordering

Operacje VoiceSession, a nie ręczne `sink.emit`, potwierdzają kolejność:

- jeden request: `1 session.ready`, `2 transcript.final`;
- dwa requesty: `1 session.ready`, `2 transcript.final`, `3 transcript.final`.
