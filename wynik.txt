3. Memory domain

- Memory jest niemutowalnym modelem Pydantic niezależnym od transportu i SQLAlchemy.
- Pola:
  id: UUID, generowany przez uuid4;
  content: str;
  source_kind: MemorySourceKind;
  session_id: UUID | None;
  metadata: dict[str, JsonValue];
  created_at: timezone-aware datetime znormalizowany do UTC.
- MemorySourceKind ma obecnie semantyczną wartość voice. Desktop i mobile nie są
  rodzajami pamięci.
- content odrzuca pusty i whitespace-only input, ale zachowuje właściwą treść wraz
  z jej niepustymi whitespace.
- metadata wymaga obiektu JSON, stringowych kluczy, rekursywnie zgodnych wartości
  oraz skończonych liczb.
- Nie dodano updated_at, ponieważ obecny use case nie ma operacji update.
- Nie dodano embeddingu, klasyfikacji, topics, sentiment ani innych pól przyszłych.

5. MemoryRepository contract

Transport-neutralny runtime-checkable Protocol definiuje:

  async create(memory: Memory) -> Memory
  async get_by_id(memory_id: UUID) -> Memory | None
  async list_recent(limit: int) -> tuple[Memory, ...]

Port operuje wyłącznie na domenowym Memory. Nie ujawnia AsyncSession, ORM ani
obiektów SQLAlchemy.

6. PostgreSQL repository

- PostgresMemoryRepository znajduje się poza application core w
  kulai_memory.persistence.
- Konstruktor przyjmuje caller-owned AsyncSession.
- create wykonuje add + flush.
- get_by_id i list_recent używają SQLAlchemy async select.
- ORM MemoryDb jest mapowany na domenowy Memory przed zwróceniem wyniku.
- Błędy infrastruktury są mapowane na bezpieczny MemoryPersistenceError, a
  oryginalny wyjątek pozostaje w __cause__ dla loggera/hosta.
- Adapter nie wykonuje commit ani rollback.
- Dodano bezpośrednie zależności hosta:
  kulai_db>=0.1.0
  sqlalchemy[asyncio]>=2.0,<3.0
- Nie instalowano nowych bibliotek; zależności były już dostępne w .venv.

7. Transaction ownership

Zastosowano kanoniczny wzorzec kulai_db:

  caller/use case
      -> AsyncSession transaction
      -> MemoryService
      -> PostgresMemoryRepository
      -> flush
      -> caller commit/rollback

Repository i service nie ukrywają granicy transakcji.
