5. Advisory lock derivation
Wspólny host helper persistence/ingestion_lock.py.
SHA-256 nad bajtami stałego prefiksu kulai_memory.ingestion.v1 plus NUL,
następnie ingestion UUID.bytes.
Pierwsze 8 bajtów digestu -> big-endian signed int64.
Parametryzowany SELECT pg_advisory_xact_lock z argumentem BIGINT.
Bez Python hash(), bez process-local persistence locka.
Deterministyczny across processes/restarts.
Kolizja jedynie serializuje niezależne UUID; tombstone lookup używa pełnego UUID.
Lock key nie jest logowany ani raportowany.
Rzeczywisty local PostgreSQL transaction isolation potwierdzony: READ COMMITTED.
Ten poziom zapewnia świeży snapshot dla tombstone check po oczekiwaniu na lock.

6. Lock ordering / deadlock safety
Ingestion: ingestion advisory lock -> tombstone check -> canonical INSERT/read.
Deletion: initial identity read bez row lock -> ingestion advisory lock ->
canonical identity re-check FOR UPDATE -> tombstone INSERT ->
canonical DELETE -> reusable vector DELETE.
Indexing: canonical FOR UPDATE -> vector upsert; nigdy nie bierze advisory locka.
Caller COMMIT/ROLLBACK zwalnia transaction-scoped locks.
Real retry/delete oraz oba indexing/delete ordering cases: PASS, brak deadlocka.
