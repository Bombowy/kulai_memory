2. Decyzje architektoniczne

- Dodano mały pakiet kulai_memory.application. Core zna wyłącznie standard library
  oraz Pydantic jako bibliotekę kontraktów.
- Transport jest odwróconą zależnością: VoiceSession emituje zdarzenia do portu
  EventSink, a konkretny adapter implementuje ten port.
- Eventy są niemutowalnymi modelami Pydantic z extra="forbid" i discriminatorem type.
- Wspólna koperta zawiera schema_version=1, session_id: UUID, sequence >= 1, type
  i typowany payload.
- W obiekcie Python session_id pozostaje UUID. event_to_jsonable konwertuje go na
  string i zwraca reprezentację bezpieczną dla JSON.
- Nie dodano event busa, brokera ani zależności od FastAPI/WebSocket/UI/SQLAlchemy.
- Pydantic dodano jako bezpośrednią zależność hosta, ponieważ publiczny core importuje
  go bezpośrednio. Pakiet był już obecny tranzytywnie; nie instalowano nowej biblioteki.

4. Publiczne API VoiceSession

  session = VoiceSession(event_sink=sink)
  session.session_id -> UUID
  session.state -> VoiceSessionState
  await session.start()
  await session.close()

- start() przełącza CREATED -> ACTIVE i emituje dokładnie jeden session.ready.
- Ponowny start w ACTIVE jest idempotentnym no-opem.
- start po CLOSED lub FAILED zgłasza bezpieczny VoiceSessionStateError.
- close() jest idempotentne. CREATED przechodzi bezpośrednio do CLOSED, a ACTIVE
  przechodzi przez CLOSING do CLOSED.
- Błąd EventSink przełącza sesję do FAILED i zgłasza
  VoiceSessionEventDeliveryError. Oryginalny wyjątek pozostaje w __cause__ dla
  hosta/loggera, ale nie trafia do publicznego ErrorEvent.
- asyncio.Lock serializuje współbieżne operacje lifecycle.

5. Pełny katalog event types i payloadów

- session.ready — SessionReadyPayload (pusty, typowany status)
- transcript.partial — TranscriptPartialPayload(text)
- transcript.final — TranscriptFinalPayload(text)
- memory.saving — MemorySavingPayload (pusty, typowany status)
- memory.saved — MemorySavedPayload(memory_id)
- rag.started — RagStartedPayload (pusty, typowany status)
- rag.context — RagContextPayload(context)
- assistant.delta — AssistantDeltaPayload(delta)
- assistant.completed — AssistantCompletedPayload(text)
- error — ErrorPayload(code, message, recoverable)

Każdy event ma type będący jednoznacznym literalem, schema_version, session_id,
sequence i konkretny payload. Nowy typ można później dopisać jako kolejny wariant
unii dyskryminowanej bez zmiany transportu istniejących eventów.

6. EventSink

EventSink jest runtime-checkable Protocol z jedną operacją:

  async emit(event: VoiceSessionEvent) -> None

VoiceSession awaituje emisję, więc zachowuje kolejność wywołań i zna wynik dostawy.
Testy używają prostego InMemoryEventSink. Nie dodano test double do kodu produkcyjnego.

7. Podłączenie przyszłych adapterów

- Desktop utworzy VoiceSession z DesktopEventSink i wywoła core bezpośrednio w tym
  samym procesie. Sink przekaże zwykłe obiekty Python do granicy UI. Nie potrzeba
  lokalnego FastAPI ani HTTP, a UI nie wykonuje SQL.
- Adapter serwerowy na VPS utworzy tę samą klasę VoiceSession. Jego WebSocketEventSink
  wywoła event_to_jsonable i prześle wynik jako JSON. Adapter nie przejmie logiki
  sesji, Memory, STT ani RAG.
- Oba adaptery korzystają z tego samego kontraktu i lifecycle.
