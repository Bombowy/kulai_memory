4. Architektura i zachowanie tożsamości mTLS

Android HTTPS/WSS -> Nginx public TLS -> verified upstream TLS + Nginx gateway cert
-> dedykowany WireGuard -> Windows raw TCP bridge -> owned127.0.0.1:8443 mTLS
Uvicorn -> scope-bound admission -> istniejący Authenticator/AuthorizationPolicy
-> FastAPI SECURE -> prywatny PostgreSQL i modele AI.

Publiczny TLS kończy Nginx: VPS widzi treść i credentials. Kompromitacja VPS jest
istotnym zagrożeniem; nie deklaruje się E2EE phone-to-GPU. Upstream TLS kończy
dopiero Uvicorn. Most nie parsuje TLS/HTTP/WS, nie czyta Authorization ani nie
modyfikuje Host. SSLObject ingress nadal zawiera rzeczywisty certyfikat Nginx;
oryginalny exact gateway SAN/pin i bearer/scopes działają bez zmian. WireGuard/IP
allowlist nie zastępuje mTLS. Brak X-Verified/HMAC, plaintext hop i drugiego bearer.

Rozważono netsh portproxy: persistent target może przeżyć ingress i nie zapewnia
wymaganych lifecycle/resource bounds. Wybrany relay ma ten sam proces i faktyczny
server socket/app/runtime. Nie może przekazywać do dowolnego LOCAL_DEV:8000.
Bridge startuje dopiero po real require_ready: SECURE, canonical0004/security0003.
Każde połączenie sprawdza runtime, a Windows adapter/address/route jest sprawdzany
przed bind i co5 s. Failure monitora zamyka proces, bez auto-recovery/fallback.
Ingress nadal nasłuchuje tylko numeric loopback; bridge tylko exact private WG IP.

Most: max32, reader/write buffers64 KiB, copies16 KiB, backpressure, connect5 s,
idle240 s, lifetime900 s, reverse half-close drain<=2 s, bounded graceful close.
Stop: zatrzymanie listenera, zamknięcie aktywnych sockets/zadań, dopiero wait_closed.
Wszystkie ścieżki cancellation/resource cleanup mają testy.
Oversized WS przez Nginx może zamknąć się jako1006 bez przekazanego1009, jeżeli
upstream odmawia podczas wysyłania frame przez Nginx. Zawsze disconnect/no write;
nie oznacza to safe-to-retry NOTE. Limit256 KiB nie został osłabiony.

Osobny explicit-IP public vhost oraz rejecting default; wymagany inventory istniejących

redirect. Public Host/SNI, exact raw paths/methods, browser Origin denial. Tylko

Forwarded/X-Forwarded-*/X-Real-IP/X-Verified*/dowolne assertions są usuwane, nie
regenerowane. Poprawny bearer z takim nieistotnym nagłówkiem pozostaje poprawny;
bez bearer nadal odmowa. Direct ingress nadal odrzuca spoofing headers.

TLS1.2/1.3; session reuse off, next_upstream off/tries1, redirect/cache off,
no buffering/disk spooling, abort propagation i fixed503 bez request_applied:false.

capabilities30r/m burst10. Idle proxy240 s dopuszcza ciągły10-min PCM;
