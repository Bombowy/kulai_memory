RZECZYWIŚCIE ZAIMPLEMENTOWANO
1. Neutralne, niemutowalne modele Pydantic i port ConversationRepository.
   Conversation: UUID, opcjonalny tytuł, created_at, last_activity_at.
   Message: UUID, UUID rozmowy i żądania, rola user/assistant, tekst, czas UTC,
   monotoniczny sequence, tryb pytania text/voice i opcjonalne UUID Memories.
   Turn/CompletedTurn/TurnWrite: kompletna para i wynik idempotentnego zapisu.
   ConversationPage/MessagePage: ograniczone strony z kursorami.
2. Adapter PostgreSQL przez obecny SQLAlchemy AsyncSession / asyncpg:
   create, append_turn, recent_messages, list_conversations.
   Każda metoda posiada własną sesję i transakcję; sesja jest domykana także
   po błędzie zakończenia transakcji. Nie trzyma transakcji podczas generowania AI.
3. append_turn przyjmuje wyłącznie gotową, kompletną parę question/answer.
   Walidacja odbywa się przed SQL. Brak API zapisu pojedynczego pytania,
   częściowej odpowiedzi, audio lub tworzenia placeholdera po błędzie.
   W jednej transakcji zapisuje identyfikator tury, obie wypowiedzi i aktualizuje
   licznik oraz aktywność rozmowy. Błąd, disconnect przed COMMIT i anulowanie
   wycofują całość. CancelledError propaguje się do wywołującego.
   Wywołujący w przyszłej integracji musi wywołać append_turn wyłącznie po
   poprawnym zakończeniu generowania — adapter nie wywołuje ani nie ocenia LLM.
4. UUID żądania jest globalnie unikalny. Identyczne ponowienie zwraca pierwotną
   parę z created=False, bez zmiany daty aktywności. Inna rozmowa, treść,
   tryb wejścia lub referencje dla tego UUID powodują IdempotencyConflict.
   Po utracie potwierdzenia już wykonanego COMMIT para pozostaje kompletna;
   ponowienie z tym samym UUID/payloadem nie duplikuje jej. To nie oznacza
   automatycznego ponawiania zapisu ani generowania nowej odpowiedzi.
5. SELECT FOR UPDATE na wierszu danej rozmowy porządkuje współbieżne zapisy
   według zdobycia blokady. Dwie rozmowy nie współdzielą tej blokady.
   Para n ma sequence 2*n-1 i 2*n. Timestamp wypowiedzi oznacza czas zapisu
   gotowej pary; obie wypowiedzi mają ten sam czas. Kolejność rozstrzyga sequence.
6. Historia jest odczytywana od najnowszego okna, ale zwracana chronologicznie.
   Kursor before_sequence pobiera starsze okno, bez OFFSET i ładowania całej bazy.
   Strona może dzielić parę na granicy okna; pełna para zawsze jest zapisana atomowo.
   Lista rozmów: last_activity_at DESC, conversation_id DESC, kursor obu pól.
   Nowa aktywność może przenieść rozmowę na początek listy; odświeżenie listy
   rozpoczyna się wtedy bez kursora. Nie jest to wielostronicowy snapshot w czasie.
7. Limity: tekst każdej wypowiedzi do 16000 znaków, tytuł do 200 znaków,
   do 20 różnych UUID referencji; strony 1..100, domyślnie 50 wiadomości / 20 rozmów.
   Zapytania pobierają najwyżej limit+1 rekordów. Puste/białe teksty, NUL,
   niepoprawne limity i kursory są odrzucane. Ograniczenia długości istnieją też w DB.
8. Referencje są miękkimi UUID Memories, tylko przy odpowiedzi. Nie kopiują
   treści Memory, nie tworzą canonical Memory i nie blokują późniejszego usunięcia
   istniejącej Memory przez FK. Dostarczenie prawidłowych cytowań pozostaje zadaniem
   późniejszej integracji RAG; ten adapter nie wyszukuje ani nie modyfikuje Memories.
