8. HTTP client design

invokeOnCancellation anuluje Call; wyjątki cancellation nie są maskowane.

Brak Retrofit i network/content logging.
Korzystano z publicznego cancellable-continuation contractu:
https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-cancellable-continuation/

9. UTF-8 request proof

Decode UTF-8 i re-encode dają te same bytes; parsed query identyczne.

10. Strict JSON parsing
Nowa biblioteka kotlinx-serialization-json 1.9.0 służy tylko do strict JSON DOM,
bez serialization compiler plugin; została skompilowana z obecnym Kotlin 2.3.
Nie użyto lenient org.json do nowych response parsers.
MemoryJson/StrictJson sprawdzają exact field sets, missing/unknown fields,
typy, canonical pełny UUID, positive Int revision/rank, finite numeric Double score,
timezone-aware OffsetDateTime. Nie ma coercion quoted number/bool ani response repair.
Preview <=200 Unicode code points; duplicate IDs w jednej stronie są odrzucane.
Answered: nonblank answer i minimum jedna citation.
Insufficient: nonblank answer i zero citations.
HTTP answer i WS completed używają tego samego parsera.
