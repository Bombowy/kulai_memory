Zmiana dotyczy wyłącznie guardu reprodukowalności. Nie zmieniono vendora, SHA manifestu, migracji, bazy danych, backup/restore ani kodu STT. Nie wykonano commit ani push.

## Poprzedni invariant

Test sprawdzał jedynie:

```text
manifest current pin == gitlink commit
```

Nie sprawdzał rzeczywistego `HEAD` checkoutu `vendor/kulai_modules` ani lokalnych zmian w jego working tree. Editable/local source mógł więc wskazywać inny commit lub zawierać niezarejestrowane modyfikacje mimo zgodności manifestu z gitlinkiem.

## Nowy invariant

Test deterministycznie wymaga:

```text
manifest current pin
    ==
gitlink commit zapisany w indeksie hosta
    ==
rzeczywisty vendor HEAD

oraz

vendor working tree == clean
```

Test wykonuje następujące kontrole:

1. `git ls-files --stage -- vendor/kulai_modules` musi zwrócić wpis vendora.
2. Wpis musi mieć tryb Git `160000`, czyli być prawdziwym gitlinkiem.
3. Ścieżka z indeksu musi być dokładnie `vendor/kulai_modules`.
4. Katalog vendora musi istnieć.
5. `git -C vendor/kulai_modules rev-parse --show-toplevel` musi wskazywać sam katalog vendora, co zapobiega przypadkowemu odziedziczeniu nadrzędnego repo przy niezainicjalizowanym submodule.
6. `kulai.project.json["kulai"]["commit"]` musi być równy SHA gitlinka.
7. `git -C vendor/kulai_modules rev-parse HEAD` musi być równy temu samemu SHA.
8. `git -C vendor/kulai_modules status --porcelain` musi zwrócić pusty wynik, również dla plików nieśledzonych.

Brak Git, brak katalogu, niezainicjalizowany submodule, błędny tryb, rozbieżność SHA lub brudny vendor powodują czytelny assertion/error. Test nie skipuje brakującego vendora i nie hardkoduje żadnego SHA.
